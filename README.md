# SrvMan — SSH-менеджер серверов для Windows

Приложение с иконкой в трее и окном-дашбордом (pywebview) для управления проектами
на удалённом Linux-сервере (целевая платформа — Alpine Linux + OpenRC) по SSH.

## Возможности

- **Деплой проекта** — клонирует/обновляет git-репозиторий на сервере, автоопределяет
  тип проекта (Node.js по `package.json`, Python по `requirements.txt`, либо своя
  команда запуска), генерирует OpenRC-сервис и запускает его.
- **Удаление проекта** — останавливает и убирает службу из автозагрузки, удаляет
  init-скрипт и каталог проекта.
- **Дашборд** — аптайм, load average, RAM/swap, место на системном диске и на
  флешке с проектами, список служб со статусами, просмотр логов.
- **Трей** — иконка со сводным статусом серверов (зелёная/красная/серая), быстрое
  открытие окна, ручное обновление статуса.

## Установка

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка серверов

При первом запуске создаётся `config.local.json` (в `.gitignore`) на основе
`config.example.json`. Серверы также можно добавлять/редактировать прямо из UI
(кнопка «+» в сайдбаре или значок шестерёнки над дашбордом).

Поля сервера:

- `host`, `port`, `user` — параметры подключения по SSH
- `auth` — `"password"` или `"key"`; при `"key"` обязательно укажите `key_path` (путь к существующему файлу)
- `projects_dir` — каталог на сервере, куда будут клонироваться проекты
  (по умолчанию `/mnt/data/projects`)
- `flash_mount` — точка монтирования диска с проектами, для отображения на
  дашборде (по умолчанию `/mnt/data`)
- Подключение по SSH теперь надёжнее: таймауты 30 секунд, 3 попытки, проверка ключевого файла.

## Запуск

```
python -m client.main
```

## Тестирование

```
pip install -r requirements.txt
pytest client/test_ssh_manager.py
```

Окно стартует скрытым — приложение живёт в трее. Клик по иконке открывает панель.

## Серверный агент

Файл [agent/srvman-agent.sh](agent/srvman-agent.sh) — единственный скрипт,
который приложение само загружает на сервер (в `/usr/local/bin/srvman-agent.sh`)
при первом подключении и после каждого изменения. Он:

- при необходимости ставит `bash`, `jq`, `git` через `apk`;
- принимает одну JSON-команду на stdin и отдаёт один JSON-ответ на stdout;
- поддерживает действия: `ping`, `metrics`, `deploy`, `remove`, `logs`,
  `start`/`stop`/`restart`.

Проекты, развёрнутые агентом, запускаются как OpenRC-службы с префиксом `srv-`
(например, проект `myapp` → служба `srv-myapp`, init-скрипт
`/etc/init.d/srv-myapp`), логи пишутся в `/var/log/srvman/<name>.log`.
Список развёрнутых проектов и их метаданные хранятся в
`<projects_dir>/../srvman/manifest.json` на сервере.

## Структура проекта

```
agent/srvman-agent.sh   — серверный shell-агент
client/
  main.py                — точка входа: окно + трей
  api.py                 — API, экспонируемое в pywebview (window.pywebview.api)
  ssh_manager.py          — SSH/SFTP через paramiko, вызов агента
  tray.py                 — иконка в трее (pystray)
  config.py                — хранение списка серверов
  ui/                       — HTML/CSS/JS дашборда
config.example.json      — шаблон конфига серверов
```
